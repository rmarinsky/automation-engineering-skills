EX-ARCH-01 · shared architecture rule

Composition over inheritance — language-agnostic

Правило

Це архітектурний підхід, не мовний синтаксис. Page/screen/components агрегуються як fields (або еквівалент composition). Inheritance дозволений лише для одного вузького stable platform contract («is-a»), не як спосіб поділити helpers.

  • Не наслідуватися заради driver/page handle, config, credentials, assertions чи helper methods.
  • Reusable domain behavior живе в named common/shared modules біля сутності, не в універсальному base.
  • Runner lifecycle (setup/teardown/preconditions) належить extension/fixture/listener seam — не BaseTest inheritance tree.
  • Кожне виключення пояснюється однією конкретною причиною і exact boundary.

Що саме погоджується

Лише архітектурний default: aggregation/composition first; inheritance only for a real platform «is-a» contract. Мовні деталі (TS PageHolder, Java/Python injection, Kakao/XCUITest screen shape) живуть у відповідних language skills.

До → після

BaseTest з login/config/helpers → framework lifecycle seam. BasePage з UI helpers → narrow platform seam + domain common modules. Немає «constructor-free» як частини цього правила.

Як агент застосує правило

Покаже конкретне дублювання, спершу спробує fields/components/fixtures, а якщо пропонує base class — напише одну конкретну причину та його exact boundary, незалежно від мови.

Language seams (не частина EX-ARCH-01)Constructor-free TypeScript PageHolder, framework-required injection у Java/Python, native screen DSL — окремі language examples вже на TS/Java/Python/mobile слайдах.
Що має довести evalАгент не додає BasePage/BaseTest заради helpers/config/assertions; composition є default; будь-який base class має одну названу platform boundary.

EX-NAME-01 · shared rule

Назви описують поведінку, а не клік або номер кейсу

Контракт іменування

  • Test name: observable result — filters projects by exact name.
  • Page action: domain verb — searchFor, createProject.
  • Assertion: expected state — projectCountShouldBe, isLoaded.
  • target… = input; expected… = oracle; actual… лише для non-retrying API/domain assertion.
  • test.step групує meaningful business action/verification у Playwright; не обгортає кожен клік.
  • Коментар додається для ticket/risk/business rule, який не видно з назви; не переказує код.
  • Локальна naming convention має перевагу над універсальним шаблоном.
test("filters projects by exact name", async ({ app }) => {
  const targetProjectName = "Manufacture light";
  const expectedVisibleProjects = 1;

  await test.step("Filter projects by exact name", async () => {
    await app.projects.open();
    await app.projects.isLoaded();
    await app.projects.searchFor(targetProjectName);
  });
  await test.step("Verify only the target project remains", async () => {
    await app.projects.projectCountShouldBe(expectedVisibleProjects);
  });
  await app.projects.projectNamed(targetProjectName).isLoaded();
});

// Low-level component only:
// clickSearchButton() is acceptable there,
// but not as a scenario-level test action.

До → після

// Reject at scenario level
test("test 1", async () => clickSearchButton());
const data = makeData();

// Prefer
test("shows matching projects", async ({ app }) => {
  const targetProject = buildProject();
  const expectedVisibleProjects = 1;
  // domain actions and a visible outcome
});

Як агент застосує правило

Agent preserves an existing repository convention when it exists. Otherwise it uses behavior-oriented names, adds test.step around a coherent business operation or outcome, does not rename public APIs just for aesthetics, and keeps technical verbs inside low-level components.

Що має довести eval: generated test contains a domain action and an observable assertion; it does not end as clickButton, test2 or a generic data variable.

Коли який source

  • @ValueSource — один literal type.
  • @CsvSource — мала literal table.
  • @MethodSource — domain case object.
  • ParameterResolver — shared dependency після source argument (наприклад Faker/session), не спосіб сховати case data.
  • Random/Faker entity не створюється під час static discovery — тільки в invocation або fixture.
  • Custom provider не робимо для one-off table.

EX-JAVA-02 · Selenide

UI page + components: scoped root, conditions замість sleeps

final class ProjectsPage {
  private final ProjectsHeader header = new ProjectsHeader(
      $("[data-testid='projects-header']")
  );
  private final ElementsCollection projectCards =
      $$("[data-testid='project-card']");

  ProjectsPage open() {
    Selenide.open("/projects");
    return this;
  }

  void isLoaded() {
    $("h1").shouldHave(exactText("Projects"));
    header.isLoaded();
  }

  void projectCountShouldBe(int expectedCount) {
    projectCards.filter(visible).shouldHave(size(expectedCount));
  }
}

final class ProjectsHeader {
  private final SelenideElement root;
  ProjectsHeader(SelenideElement root) { this.root = root; }
  void isLoaded() {
    root.shouldBe(visible);
    root.$("[data-testid='project-search']").shouldBe(visible);
  }
  void searchFor(String projectName) {
    root.$("[data-testid='project-search']").setValue(projectName);
  }
}

Обов'язкові межі

  • Component має власний scoped root.
  • Кожен page/component має власний isLoaded() з ключовими елементами.
  • open() лише navigates; scenario викликає isLoaded() явно, коли readiness є частиною test evidence.
  • shouldBe/shouldHave — assertion і dynamic wait; не getText() + static assertion.
  • Thread.sleep не комітимо.
  • Спершу semantic selector; якщо його нема — request на data-testid, ARIA або accessibility attribute.
  • XPath — тільки documented fallback, не default.

PageHolder + Application, arrow locator factories, components as fields

export abstract class PageHolder {
  constructor(protected readonly page: Page) {}
}

export class Application extends PageHolder {
  readonly projects = new ProjectsPage(this.page);
}

export class ProjectsPage extends PageHolder {
  private readonly heading = (): Locator =>
    this.page.getByRole("heading", { name: "Projects", exact: true });
  readonly header = new ProjectsHeader(this.page);
  readonly grid = new ProjectGrid(this.page);

  async open(): Promise<void> {
    await this.page.goto("/projects");
  }

  async isLoaded(): Promise<void> {
    await expect(this.heading()).toBeVisible();
    await this.header.isLoaded();
    await this.grid.isLoaded();
  }
}

final class ResponseDecorator {
  private final Response response;
  ResponseDecorator(Response response) { this.response = response; }

  ResponseDecorator shouldHaveStatus(int expectedStatus) {
    response.then().statusCode(expectedStatus);
    return this;
  }

  <T> T as(Class<T> responseType) {
    return response.as(responseType);
  }
}

final class SuitesController {
  ResponseDecorator create(SuitesRequest targetSuite) {
    return new ResponseDecorator(given()
        .contentType("application/vnd.api+json")
        .body(targetSuite)

  }

Response decorator contract

data/ owns simple entity builders; controller owns request execution; response decorator performs the explicit status assertion and deserializes only after it. Test chooses the expected status, then receives a typed response for domain assertion.

One narrow transport/auth base may exist only if concrete repositories already require it; it must not absorb data builders, credentials or scenario assertions.

EX-MOBILE-01 · mobile strategy

Native first: XCUITest / Kakao / Detox. Appium — cross-platform fallback.

Selection rule

  • iOS native: XCUITest.
  • Android native: Kakao, not raw Espresso as the public skill surface.
  • React Native: Detox.
  • Cross-platform / existing shared suite: Appium only if its value exceeds native coverage cost; це найнижчий priority.
  • Accessibility IDs and other native locators are OK; XPath never — improve testability first.

API-first pre/postcondition (Mobile API precondition contract)

  • Спочатку автоматизуй/використовуй backend/API для setup і cleanup mobile сценаріїв.
  • Окремий vendor/team з власними automation tools і testers — допустимий виняток; інакше API до максимуму.
  • Precondition: створити стан через API/GraphQL/gateway seam.
  • Postcondition: прибрати стан через той самий seam — спрощує flaky UI cleanup.
  • UI перевіряє user-visible journey, не будує довгий state кліками.

Deep links + local system context

  • Деталізувати deep links, щоб відкривати потрібний screen швидко, без навігаційного шуму.
  • Просити clone локально поруч із autotest repo усього, що автоматизується: mobile app, frontend, BFF/proxy, GraphQL/gateway, backend services, DB-related repos — system under test для LLM context.
  • З цього context — пропозиції з testability (IDs, deep links, API seams).
  • Це правило переважно для architecture / structure agent, не для кожного language skill agent.

Mobile decision tree

  1. Чи є API/OpenAPI/GraphQL seam для pre/postcondition? Якщо так — використати його.
  2. iOS native → XCUITest · Android native → Kakao · RN → Detox.
  3. Deep link / accessibility ID відсутні? Запропонувати product-side testability change.
  4. Appium — лише коли shared cross-platform suite реально дешевший за native duplication.

EX-CI-01 · regression operating contract

Fail-fast CI gate: tiny environment proof перед повною regression

Pipeline order

  1. Install/build/typecheck — dependency and runner health.
  2. Preflight — one or a few isolated tests prove base URL, auth/test data seam and a critical read/write path in the controlled test environment.
  3. Full regression — starts only when preflight is green; shard/parallelism comes after isolation evidence.

Preflight failure is a signal to stop: it must not consume CI on a full suite that cannot be trusted.

What qualifies as preflight

  • Small, deterministic and independently cleaned-up.
  • Uses the same credentials/base URL/artifact wiring as regression.
  • Does not mutate production and does not depend on the rest of the suite.
  • Retries are not used to hide environment failure.
